# 1 进程

| 序号 | IPC 方式         | 传输速度 | 跨机器支持 | 关键特点                                                     |
| ---- | ---------------- | -------- | :--------: | ------------------------------------------------------------ |
| 1    | 共享内存         | 最快     |     否     | 直接映射物理内存，无需数据复制，适合超大数据量（如图像、视频帧）。 |
| 2    | 匿名管道         | 快       |     否     | 父子进程间单向通信，基于内存，无网络开销。                   |
| 3    | 本地命名管道     | 快       |     否     | 同一机器内任意进程双向通信，基于内存，无网络开销。           |
| 4    | 网络命名管道     | 中       |     是     | 基于 SMB 协议，需开放 TCP 445 端口，适合中小数据量的 Windows 跨机器通信。（linux系统无直接等效物） |
| 5    | 套接字（UDP）    | 快       |     是     | 无连接，不可靠传输，低延迟，适合实时性要求极高的场景（如音视频流）。跨语言、跨平台。 |
| 6    | 套接字（TCP)     | 中       |     是     | 可靠传输，需建立连接和流量控制，适合任意数据量的跨平台通信。跨语言、跨平台。 |
| 7    | 消息队列（MSMQ） | 慢       |     是     | 异步通信，支持事务和持久化，适合企业级可靠消息传递（如订单系统）。 |

# 2 线程

## 2.1 单线程

单线程程序有简单、资源占用少的特点。

## 2.2 多线程

采用多线程技术的目的无非是提高平均响应速度和实现并发。在使用多线程时，要明确每个线程的任务，线程可以分为UI线程，IO线程，计算线程，第三方库线程等。

**Linux能同时开启多个线程？**

对于32位系统来说，一个进程的地址空间是2^32 = 4G，用户态能使用2G，一个线程的默认栈大小为8M，则可以开启256个线程。

**为什么第三方库要单独使用一个线程？**

职责分离：使用第三方库一般是为了实现某一特定功能。

线程安全：第三方库的实现可能未考虑到线程安全，所以使用单一线程执行。

**线程池大小如何设置比较合适？**

**阻抗匹配原则**：合适的线程数量 = 系统CPU数量 / 任务的计算时间占比
