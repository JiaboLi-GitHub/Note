# 1 基础

## 1.1 音频基础

### 1.1.1 音频信号数字化

**采样**：将连续声波按固定频率采样。采样率越高音质越接近原始声音。人类听觉频率范围是20Hz~20KHz，根据采样定律，采样频率要大于40KHz。一遍采样频率是44.1KHz，即一秒采样44100次。

**量化**：将采样值转换为数字信号，位深决定量化的精度。

**编码**：将数字信号压缩为音频格式，分为有损编码和无损编码。

![img](resource/format,webp.webp)

### 1.1.2 常见的音频编码格式

| 格式 | 编码类型 | 特点                          | 应用场景           |
| ---- | -------- | ----------------------------- | ------------------ |
| MP3  | 有损     | 压缩率高，音质中等            | 音乐播放、网络音频 |
| AAC  | 有损     | 音质优于MP3，苹果设备默认格式 | 流媒体             |
| WAV  | 无损     | 未压缩，体积大                | 音频编辑、专业录音 |
| FLAC | 无损     | 压缩率高且保留所有数据        | 高清音乐下载       |

### 1.1.3 关键指标

- 频率——音调
- 振幅——音量
- 波形——音色

**采样**：将连续声音描述为离散的数字信号。

**采样率**：每秒采集多个样本。

**采样位数**（采样大小/量化位数）：每个采样点用多少比特表示。

奈奎斯特**采样定律**：采样率大于或等于连续信号最高频率分量的两倍时，采样信号可以用来完美重构原始连续信号。

**通道数**：声音的通道数量，常见的有单声道和双声道。

**声音帧**：按照一定的时间间隔组织的一组音频样本。

**比特率**：编码前，音频每秒钟播放的数据量，单位是bit。例如PCM流，采样率位44100Hz，采样大小位16，声道数为2，那么码率为：44100 * 16 * 2 bit。

**码率**：编码后，音频每秒钟播放的数据量，单位是bit。

## 1.2 视频基础

### 1.2.1 视频的基础构成

**像素**：视频图像的最小单位，单个像素由色彩空间（如RGB、YUV）表示。

**分辨率**：横向像素数 * 纵向像素数。

- 标清（SD）：720×480（NTSC）、720×576（PAL）
- 高清（HD）：1280×720（720p）、1920×1080（1080p）
- 超高清（UHD）：3840×2160（4K）、7680×4320（8K）

**帧率**：每秒播放的画面数。

**Stride（跨距）**：指在内存中每行像素所占的空间。为了实现**内存对齐**每行像素在内存中所占的空间并不一定是图像的宽度。

例如638*480的RGB24图像，内存以16字节对齐。638 * 3 % 16 = 10，所以想要在末尾添加6个字节，即2个像素。

### 1.2.2 色彩空间

RGB：红（R）绿（G）蓝（B）。

YUV：Y表示明亮度，也就是灰阶值，U和V表示色度。

**YUV亮度和色度分离的好处：**

- 兼容黑白电视和彩色电视。
- 降低色度的存储大小，不会对图像质量影响太大。（人眼对亮度敏感，对色度不敏感）
- 便于编码。

**RGB与YUV转换标准：**

- BT.601标准（适用于SDTV，标清视频）
- BT.709标准（适用于HDTV，高清视频）
- BT.2020标准（适用于4K/8K超高清视频）

**YUV采样方法：**

- YUV4:4:4：一个Y分量对应着一个U分量和一个V分量。
- YUV4:2:2：水平方向下两个Y分量共用一个U分量和一个V分量。
- YUV4:2:0：正方形区域内四个像素使用四个Y分量，一个U分量和一个V分量。

为什么解码失败显示绿屏？

因为解码失败YUV默认为0，根据YUV转换RGB公式可得转换后为绿色。

```C++
void yuv_to_rgb_bt709_fixed(uint8_t y, uint8_t u, uint8_t v, uint8_t* r, uint8_t* g, uint8_t* b) {
    int y_val = y;
    int u_val = u - 128; // 偏移U
    int v_val = v - 128; // 偏移V

    // 使用16位定点数（乘以256）
    int r_val = y_val + ((1.5748f * 256) * v_val) / 256;
    int g_val = y_val - ((0.1873f * 256) * u_val) / 256 - ((0.4681f * 256) * v_val) / 256;
    int b_val = y_val + ((2.0421f * 256) * u_val) / 256;

    // 限制范围
    *r = (uint8_t)fmax(0, fmin(255, r_val));
    *g = (uint8_t)fmax(0, fmin(255, g_val));
    *b = (uint8_t)fmax(0, fmin(255, b_val));
}
```

### 1.2.3 视频压缩算法

**概念**：

I帧：帧内编码帧，是视频序列中的独立帧，不依赖如何其他帧即可完成解码。

P帧：向前预测编码帧，通过参考前一帧（I帧或P帧）的差异进行编码。

B帧：双向预测编码帧，同时参考前一帧和后一帧进行编码。

# 2 功能

## 2.1 **音视频同步**

**为什么需要进行音视频同步？**

当计算机调度系统负载过高时，视频、音频及字幕线程易出现响应延迟，进而导致媒体实际播放时间与既定 PTS（Presentation Time Stamp，显示时间戳）产生偏差。我们的优化目标不仅在于缩小单种媒体的实际播放时间与既定 PTS 之间的误差，更需确保视频、音频、字幕等不同媒体在播放过程中的时间同步精度，以减少彼此间的偏差。

DTS：解码时间戳，这个时间戳的意义在于告诉播放器该在什么时候解码这一帧的数据。

PTS：显示时间戳，这个时间戳用来告诉播放器该在什么时间显示这一帧的数据。

Time Base（时间基）：视频流的时间单位，定义为AVRational结构体（包含分子num和分母den）。例如：{1， 90000}表示每个时间单位为1/90000秒。

将PTS转换为实际时间：

```
int64_t timeStamp = pts * av_q2d(timeBase) * 1000000; // 微秒
```

**同步方式**

以音频为基准：当视频播放过快时，拉长视频帧播放时长。当视频帧播放过慢时，缩短视频帧播放时长或丢弃视频帧。

以视频为基准：当音频播放过快时，拉长音频帧播放时长。当音频帧播放过慢时，缩短音频帧播放时长。一般不会丢弃音频帧。

以外部时钟为基准。

因为人耳对应音频的连续性会更加敏感，并且音频数据的连续性更强（帧切得更细），所以一般以音频为基准。在同步时也不会丢弃音频帧。

## 2.3 滤镜

Look Up Table（简称 LUT，查找表）是 “空间换时间” 的优化技术：输入一个值，通过查表直接获取输出值。在调色领域，颜色查找表（RGB 分量）可将预设颜色值存储其中，需用时通过索引快速定位对应颜色，大幅降低 GPU 运算量。

在滤镜 LUT 应用中，3D LUT 预存效果 RGB 值。8bit RGB 色域本需 256×256×256（约 16M）的完整存储，实际无需全存，只需保留关键节点，节点间颜色通过线性插值获取即可。

![img](test.assets/172c7fa7de8a1671tplv-t2oaga2asx-jj-mark3024000q75.png)

LUT滤镜的主要存储格式为cuba、png。

### 2.3.1 cube

**头部元信息**

- TITLE：滤镜名称。
- LUT_3D_SIZE：采样密度。
- DOMAIN_MIN：输入值的归一化范围。
- DOMAIN_MAX：输出值的归一化范围。

**数据部分**

每行3个浮点数，分别表示RGB，总行数LUT_3D_SIZE^3。数据按照R->G->B顺序排列。

```tex
0.000000 0.000000 0.000000  // 输入 (R=0, G=0, B=0) 对应的输出
0.030303 0.030303 0.030303  // 输入 (R=1/LUT_3D_SIZE, G=0, B=0) 对应的输出
0.060606 0.060606 0.060606  // 输入 (R=2/LUT_3D_SIZE, G=0, B=0) 对应的输出
...
```

### 2.3.2 png

图片滤镜本质是颜色方块的二维化呈现。以 512×512 分辨率为例，图中含 8×8 个大格子，每个大格子内有 64×64 个小格子存色彩像素；小格子 X 轴对应 R 通道（0-255）、Y 轴对应 G 通道（0-255），B 通道分量按 8×8 大格子的行列顺序分布，最终叠加 RGB 三通道形成完整色彩。

![img](test.assets/172c7fa7ddae5230tplv-t2oaga2asx-jj-mark3024000q75.png)

```glsl
// 精度定义（适配移动端/低性能设备）
precision mediump float;

// 外部输入：原始图像纹理、LUT滤镜纹理、滤镜强度
uniform sampler2D InputImageTexture;   // 待处理的原始图像
uniform sampler2D InputImageTexture2;  // 存储滤镜效果的LUT纹理（512x512，8x8大格子）
uniform lowp float intensity;          // 滤镜强度（0=无效果，1=全效果）

// 顶点着色器传递的纹理坐标
varying vec2 TextureCoordinate;

void main() {
    // 1. 取原始图像当前像素颜色
    vec4 originalColor = texture2D(InputImageTexture, TextureCoordinate);

    // 2. 用B通道值计算LUT大格子索引（8x8=64格，B值0-1映射到0-63）
    float blueIndex = originalColor.b * 63.0;
    // 取B值对应的两个相邻大格子（减少插值误差）
    vec2 grid1 = vec2(
        mod(floor(blueIndex), 8.0),  // 格子X坐标（0-7）
        floor(floor(blueIndex)/8.0)  // 格子Y坐标（0-7）
    );
    vec2 grid2 = vec2(
        mod(ceil(blueIndex), 8.0),   // 相邻格子X
        floor(ceil(blueIndex)/8.0)   // 相邻格子Y
    );

    // 3. 计算LUT纹理中具体采样坐标（R/G通道控制格子内小像素位置）
    vec2 getLutPos(vec2 grid) {
        float gridSize = 1.0/8.0;    // 大格子占LUT纹理的比例（512/8=64像素）
        float pixelOffset = 0.5/512.0;// 避开像素边缘，采样更精准
        // 格子偏移 + 内部R/G通道偏移
        return grid * gridSize + pixelOffset + (gridSize - 2.0*pixelOffset) * originalColor.rg;
    }
    vec2 lutPos1 = getLutPos(grid1);
    vec2 lutPos2 = getLutPos(grid2);

    // 4. 从LUT取滤镜颜色，相邻格子颜色插值平滑过渡
    vec4 lutColor1 = texture2D(InputImageTexture2, lutPos1);
    vec4 lutColor2 = texture2D(InputImageTexture2, lutPos2);
    vec4 filterColor = mix(lutColor1, lutColor2, fract(blueIndex));

    // 5. 混合原始色与滤镜色，按强度控制效果
    gl_FragColor = mix(originalColor, vec4(filterColor.rgb, originalColor.a), intensity);
}
```

## 2.4 转场

**闪黑过渡**

```glsl
// 版本和精度定义（兼容不同设备和GLSL版本）
#version 100
#ifdef GL_ES
#extension GL_EXT_gpu_shader4 : enable
precision mediump float; // 中等精度浮点计算
#endif

// 兼容不同GLSL版本的变量定义
#if __VERSION__ == 120 || __VERSION__ == 100
#define FragColor gl_FragColor
#define textureCoordinate vertexColor
#define texture texture2D
varying vec2 textureCoordinate; // 纹理坐标
#else
in vec2 textureCoordinate;
out vec4 FragColor;
#endif

// 输入：源图像、目标图像、过渡进度(0.0-1.0)
uniform sampler2D texFrom;  // 过渡前的图像
uniform sampler2D texTo;    // 过渡后的图像
uniform float factor;       // 过渡进度(0→1)

void main() {
    vec4 blackColor = vec4(0.0); // 黑色
    
    if (factor < 0.5) {
        // 前半段(0.0→0.5)：源图像逐渐变黑
        float progress = factor * 2.0; // 映射到0.0→1.0
        FragColor = mix(texture(texFrom, textureCoordinate), blackColor, progress);
    } else {
        // 后半段(0.5→1.0)：从黑色逐渐显示目标图像
        float progress = (1.0 - factor) * 2.0; // 映射到1.0→0.0
        FragColor = mix(texture(texTo, textureCoordinate), blackColor, progress);
    }
}
```

**旋转过渡**

```glsl
// 1. 版本与精度配置：兼容低版本GLSL和移动设备
// 声明使用GLSL 100版本（适配多数移动端GPU和旧渲染设备）
#version 100

// 针对GL_ES环境（移动端/嵌入式）的特殊配置
#ifdef GL_ES
// 启用GPU着色器4扩展，支持更多纹理操作和精度控制
#extension GL_EXT_gpu_shader4 : enable
// 根据设备支持的精度，选择高/中精度浮点计算（平衡画质与性能）
#ifdef GL_FRAGMENT_PRECISION_HIGH
precision highp float;
#else
precision mediump float;
#endif
#endif

// 2. 跨版本变量兼容：统一不同GLSL版本的输出/输入和函数命名
#if __VERSION__ == 120 || __VERSION__ == 100
// 低版本（100/120）：颜色输出变量名、纹理坐标变量名、纹理采样函数名适配
#define FragColor gl_FragColor       // 颜色输出变量（低版本固定为gl_FragColor）
#define textureCoordinate vertexColor // 纹理坐标变量（低版本通过varying传递，别名统一）
#define texture texture2D             // 2D纹理采样函数（低版本为texture2D）
varying vec2 textureCoordinate;      // 低版本：从顶点着色器传递的纹理坐标（0-1范围）
#else
// 高版本（如330+）：输入输出变量声明方式适配
in vec2 textureCoordinate;   // 高版本：纹理坐标输入（用in关键字）
out vec4 FragColor;          // 高版本：颜色输出（用out关键字）
#endif

// 3. 外部输入参数：从CPU端传递的uniform变量（转场核心配置）
uniform sampler2D texFrom;    // 过渡前的源图像纹理（转场开始时显示的图像）
uniform sampler2D texTo;      // 过渡后的目标图像纹理（转场结束时显示的图像）
uniform float factor;         // 转场进度（0.0=完全显示texFrom，1.0=完全显示texTo，0.5=中间状态）
uniform float textureWidth;   // 图像宽度（像素），用于计算实际坐标
uniform float textureHeight;  // 图像高度（像素），用于计算实际坐标

// 4. 全局变量：存储图像分辨率（宽高），避免重复计算
vec2 resolution;

// 5. 工具函数1：三次贝塞尔曲线计算（用于实现平滑的进度缓动）
// 参数：p0(起点)、p1/p2(控制点)、p3(终点)、t(原始进度0-1)
// 返回：缓动后的进度值（让转场速度从快到慢，更自然）
vec2 lm_cubic_bezier(vec2 p0, vec2 p1, vec2 p2, vec2 p3, float t)
{
    float t_inv = 1.0 - t;          // t的反向值（1-t）
    float t_inv_2 = pow(t_inv, 2.0); // (1-t)的平方
    float t_inv_3 = pow(t_inv, 3.0); // (1-t)的立方
    float t_2 = pow(t, 2.0);        // t的平方
    float t_3 = pow(t, 3.0);        // t的立方
    
    // 三次贝塞尔曲线公式：线性组合4个控制点，计算当前t对应的位置
    vec2 p = p0*t_inv_3 + 3.0*p1*t*t_inv_2 + 3.0*p2*t_2*t_inv + p3*t_3;
    return p;
}

// 6. 核心函数：实现图像旋转扭曲效果（转场的视觉核心）
// 参数：tex(目标纹理)、uv(纹理坐标)、center(扭曲中心点)、zoom(缩放因子)、radius(扭曲半径)、angle(总旋转角度)
// 返回：扭曲后的纹理颜色
vec4 lm_twirl(sampler2D tex, vec2 uv, vec2 center, float zoom, float radius, float angle)
{
    vec2 texSize = resolution;      // 获取图像分辨率（宽高，像素单位）
    vec2 tc = uv * texSize;         // 将纹理坐标（0-1）转换为像素坐标（如uv=(0.5,0.5)→tc=(256,256)）
    tc -= center;                   // 坐标平移：将中心点作为原点（方便计算旋转）
    
    // 计算当前像素到中心点的距离（用于判断是否在扭曲范围内）
    float dist = length(tc);
    
    // 仅对中心点周围"radius"范围内的像素进行扭曲（范围外像素保持不变）
    if (dist < radius)
    {
        // 计算扭曲强度：距离中心点越近，扭曲越强（percent越接近1）
        float percent = (radius - dist) / radius;
        // 计算当前像素的旋转角度：percent越大，旋转角度越大（radians将角度转为弧度）
        float theta = percent * radians(angle);
        
        // 转场前半段（factor<0.5）反向旋转，后半段正向旋转，增强转场对称性
        if (factor < 0.5)
            theta = -theta;
        
        // 旋转矩阵参数：sin(theta)和cos(theta)
        float s = sin(theta);
        float c = cos(theta);
        
        // 应用2D旋转：通过点积计算旋转后的坐标（顺时针旋转theta角）
        tc = vec2(dot(tc, vec2(c, -s)), dot(tc, vec2(s, c)));
    }
    
    // 应用缩放：随进度缩小图像（增强扭曲的视觉层次）
    tc *= 1.0 - zoom * 0.5;
    // 坐标平移回原坐标系（恢复中心点位置）
    tc += center;
    // 将像素坐标转回纹理坐标（0-1范围），用于采样纹理
    tc = tc / texSize;
    
    // 采样扭曲后的纹理颜色并返回
    vec4 resultColor = texture(tex, tc);
    return resultColor;
}

// 7. 主函数：转场逻辑入口（整合所有步骤，输出最终颜色）
void main()
{
    // 初始化分辨率：将CPU传递的宽高转为vec2（像素单位）
    resolution = vec2(textureWidth, textureHeight);
    vec2 t_screen_size = resolution;          // 屏幕/图像尺寸（像素）
    vec2 t_real_uv = textureCoordinate * t_screen_size; // 纹理坐标→像素坐标（备用，未实际使用）
    vec2 t_center = 0.5 * t_screen_size;      // 计算图像中心点（像素坐标，如512x512图像→(256,256)）
    
    // 计算原始进度：将factor(0-1)映射到0-1-0范围（前半段0→1，后半段1→0）
    float t_progress = factor * 2.0;          // factor<0.5时：0→1
    if (factor > 0.5)
    {
        t_progress = (1.0 - factor) * 2.0;    // factor>0.5时：1→0
    }
    
    // 配置贝塞尔曲线控制点：此处p1/p2=(1,0)，实现"先快后慢"的缓动效果
    vec2 p0 = vec2(0.0);  // 曲线起点（t=0时，进度0）
    vec2 p3 = vec2(1.0);  // 曲线终点（t=1时，进度1）
    vec2 p1 = vec2(1, 0); // 第一个控制点
    vec2 p2 = vec2(1, 0); // 第二个控制点
    
    // 应用贝塞尔缓动：将原始进度转为平滑进度（优化转场的速度变化）
    t_progress = lm_cubic_bezier(p0, p1, p2, p3, t_progress).y;
    
    // 计算转场参数：随缓动进度变化
    float zoom = t_progress;                  // 缩放因子：进度越大，缩放越明显
    // 扭曲半径：进度越大，扭曲范围越广（基础半径为中心点到边缘的距离，叠加进度补偿）
    float radius = length(t_center) * (1.0 + t_progress * 0.55);
    float angle = 450.0 * t_progress;         // 总旋转角度：进度越大，旋转角度越大（最大450度）
    
    // 分阶段应用转场：
    // 前半段（factor<0.5）：扭曲源图像（texFrom），逐渐过渡到中间状态
    if (factor < 0.5) {
        FragColor = lm_twirl(texFrom, textureCoordinate, t_center, zoom, radius, angle);
    } 
    // 后半段（factor≥0.5）：扭曲目标图像（texTo），从中间状态过渡到最终画面
    else {
        FragColor = lm_twirl(texTo, textureCoordinate, t_center, zoom, radius, angle);
    }
}
```

# 3 封装格式

## 3.1 FLV

FLV文件由文件头和文件体组成，文件体由多个上一标签大小和标签组成。标签有元数据标签、视频标签和音频标签三种类型。每个标签都是由标签头和标签数据组成，不同类型标签的标签头格式是相同的，不同的是标签数据。

![image-20250822101750676](resource/image-20250822101750676.png)

上图已标出**元数据标签**的格式。

**视频标签**的标签数据包含**帧类型**、**视频编码格式**、**包类型**、**时间补偿**、**数据**。数据的内容由视频编码格式和包类型决定。

当编码类型为AVC时，包类型有三种：

1. 包类型 = 0，代表后面的数据是 AVC 序列头
2. 包类型 = 1，代表后面的数据是 AVC NALU 单元
3. 包类型 = 2，代表 AVC 序列结束

时间补充是用来计算B帧场景的PTS，标签头的时间戳是解码时间（DTS），加上时间补偿才是PTS。

音频标签的标签数据包含**音频编码格式**、**采样率**、**采样深度**、**声道**、**包类型**、**数据**。数据的内容由音频编码格式和包类型决定。

当音频编码类型为ACC，包类型有两种：

1. 包类型 = 0，数据为ACC序列头。
2. 包类型 = 1，数据为ACC帧数据。

## 3.2 MP4

MP4文件是由多个Box作为节点组成的树形结构文件。Box由两部分组成，分别是Box Header和Box Body。

**Box Header**

- Box Type：分为预定义类型和自定义类型。“uuid”表示自定义类型。
- Box Size：等于0时代表这个Box是文件的最后一个Box，等于1时，代表后面定义一个8字节的largesize表示Box大小。
- Largesize：Box Size = 1时存在。
- Version和Flags：Full Box时存在。
- Extended Type：代表自定义值，Box Type = uuid存在。16字节。

# 4 编解码

## 4.1 媒体文件冗余因素

1. 空间冗余：图像相邻像素之间有较强的相关性。
2. 时间冗余：视频序列的相邻图像之间内容相似。
3. 编码冗余：不同像素值出现的概率不同。
4. 视觉冗余：人的视觉系统对某些细节不敏感。
5. 知识冗余：规律性的结构可由相关知识得到。

## 4.2 编码技术

本文主要介绍H.265编码原理。

### 4.2.1 编码结构

H.265编码结构分为两层：

- **视频编码层**（VCL）：负责视频压缩，流程为图片方块->块的预测生成残差（帧内预测/帧间预测）->残差变换->变换系数矩阵量化->熵编码。
- **网络提取层**（NAL）：定义数据封装格式，将视频编码层生成的数据封装为网络提取层单元数据包，适配不同网络环境传输。

### 4.2.2 编码环节

**分块**

首先将视频序列分为若干**图像组**（GOP），接着采用四叉树划分法划分出编码块，编码块划分出**预测块**和**变换块**。

**预测**

利用帧内的空间冗余和帧间的时间冗余生成预测值，仅传输预测值与真实值的**残差**以去除冗余。预测分为帧内预测和帧间预测。

**变换**

将预测生成的残差从**空间域**转换到**频域**，进一步去除空间冗余。

**量化**

以变换单元为单位，通过**量化参数**控制步长，对频域变换系数进行有损压缩，量化参数越大压缩率越高，但失真越明显，反之则码率高，画质好。这一补充是去除视觉冗余。

**熵编码**

采用自适应二进制算术编码，按数据概率分布用更紧凑的编码标记量化后的数据。这一步骤是去除编码冗余。

**环路滤波**

包含去方块滤波和样点自适应补偿，分别用于消除块编码导致的块效应和振铃效应，优化重建图像的视觉质量。

















































**帧内预测**

对 I 帧（关键帧）的每个块，通过参考相邻已编码像素预测当前块内容，只编码预测误差，减少空间冗余。
